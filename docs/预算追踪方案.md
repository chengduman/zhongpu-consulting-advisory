## 一、方案概述

本方案在中普咨询品牌站建立 **自动预算追踪机制**，覆盖 DeepSeek API 调用相关的预算规划、实时监控、异常预警和审核流程。

### 核心目标

1. **自动化**：通过脚本定期检查 DeepSeek 账户余额，自动生成报告
2. **可追溯**：所有预算变动记录在 `data/budget/` 目录，支持历史回溯
3. **流程化**：运营部预算审核流程写入授权体系，与财务部联动
4. **预警及时**：三级预警机制确保预算异常时快速响应

## 二、自动预算追踪脚本

### 2.1 脚本说明

| 项目 | 内容 |
|:----|:----|
| **脚本路径** | `scripts/budget-report.py` |
| **运行方式** | `python scripts/budget-report.py` |
| **依赖** | Python 3.8+，requests（可选，仅 API 模式需要） |
| **数据存储** | `data/budget/deepseek_balance.csv`（明细日志） |
| **历史记录** | `data/budget/balance_history.json`（结构化状态） |

### 2.2 工作流程

```
┌─────────────────────────────────────────────┐
│  运行 budget-report.py                       │
├─────────────────────────────────────────────┤
│  [Step 1] 查询 DeepSeek API 余额             │
│    ├─ ✅ 成功 → 使用实时余额                  │
│    └─ ⚠️ 失败 → 从本地记录推断余额            │
│                                              │
│  [Step 2] 计算预估日消耗                      │
│    ├─ 默认: 150K input + 50K output tokens   │
│    └─ 定价: deepseek-chat $0.14/$0.28 每M    │
│                                              │
│  [Step 3] 预算状态评估                        │
│    ├─ 🟢 ≥50% → 充足，无需操作                │
│    ├─ 🟡 ≥20% → 注意，建议关注                │
│    ├─ 🟠 ≥10% → 警告，减少非必要调用          │
│    └─ 🔴 <10% → 紧急，立即处理               │
│                                              │
│  [Step 4] 保存日志到 CSV + JSON               │
└─────────────────────────────────────────────┘
```

### 2.3 配置说明

脚本通过以下方式配置：

| 配置项 | 方式 | 默认值 | 说明 |
|:------|:----|:------|:----|
| DeepSeek API Key | 环境变量 `DEEPSEEK_API_KEY` | — | 设置后可实时查余额 |
| 月度预算 | `DEFAULT_MONTHLY_BUDGET` | $100.00 | 可在脚本顶部修改 |
| 初始余额 | `DEFAULT_STARTING_BALANCE` | $100.00 | 首次运行时的基础余额 |
| Token 消耗估算 | `ESTIMATED_USAGE` | 150K/50K 日 | 根据实际运营数据更新 |

### 2.4 定价依据

参考 DeepSeek 官方定价及中普咨询成本模型（`gists/multi-agent-cost-model.md`）：

| 模型 | 输入（每百万 tokens） | 输出（每百万 tokens） |
|:----|:-------------------:|:--------------------:|
| deepseek-chat | $0.14 | $0.28 |
| deepseek-coder | $0.14 | $0.28 |
| deepseek-r1 | $0.55 | $2.19 |

## 三、运营部预算审核流程

详见 [授权体系与部门自治制度](/docs/授权体系与部门自治制度.md) 第 3.7.1〜3.7.2 节。

### 3.1 审核层级

| 预算范围 | 审核路径 | 时限 |
|:--------|:--------|:----:|
| ≤$5k | 运营部自主审核 → 财务部备案 | 2h |
| $5k~$20k | 运营部初审 → 财务部复核 → CEO确认 | 6h |
| >$20k | 运营部提案 → 财务部审核 → CEO审批 | — |

### 3.2 偏差管理

| 偏差 | 等级 | 响应 |
|:---:|:----:|:----|
| <10% | 🟢 正常 | 运营部自主管理 |
| 10%~20% | 🟡 注意 | 书面说明 → 财务部备案 |
| >20% | 🔴 超支 | 暂停项目 → 上报CEO审批 |

## 五、后续优化建议

1. **设置 API Key**：配置 `DEEPSEEK_API_KEY` 环境变量以启用实时余额查询
2. **Cron 定时任务**：每周一自动运行脚本，发送报告到运营部/财务部
3. **多模型追踪**：扩展脚本支持 Claude、GPT-4o 等多模型预算跟踪
4. **可视化看板**：将 CSV 日志接入 Grafana 或简单 HTML 看板
5. **GitHub Actions 集成**：在 CI/CD 中自动检查预算，合并 PR 前验证余额
