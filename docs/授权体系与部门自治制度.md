## 一、制度目的

消除"CEO审批一切"的瓶颈，建立**部门自治、例外上报**的高效运营体系。各部门在授权范围内自主决策、自主执行，CEO仅参与战略方向把控和例外事项处置。

## 二、授权基本原则

| 原则 | 说明 |
|:---:|------|
| 🟢 **充分授权** | 部门职责范围内的事务，部门负责人独立决策 |
| 🟡 **例外上报** | 超出授权阈值或跨部门冲突时，上报CEO |
| 🔴 **保障底线** | 部门负责人有义务在授权范围内做出最佳判断 |
| 🔄 **可追责** | 授权不卸责——各部门对自己的决策和交付质量负责 |

### 3.7.1 运营部 · 预算审核流程

运营部涉及预算事项时，须遵循以下审核流程：

```
项目发起（运营部）
    │
    ├── 预算≤$5k ──────────────────────── 运营部自主审核 → 执行
    │
    ├── 预算$5k~$20k ── 运营部初审 ── 财务部复核 ── CEO确认 → 执行
    │
    └── 预算>$20k ──── 运营部提案 ── 财务部审核 ── CEO审批 → 执行
```

| 步骤 | 责任方 | 操作 | 时限 |
|:----:|:------:|:----|:----:|
| ① 预算编制 | 运营部·徐明辉 | 根据项目需求编制预算明细，注明 DeepSeek/LLM API 费用占比 | 项目启动前 |
| ② 自审（≤$5k） | 运营部·徐明辉 | 在授权范围内自主审批，报财务部备案 | 2小时内 |
| ③ 复核（$5k~$20k） | 财务部·陆正明 | 审核预算合理性，输出审核意见书 | 4小时内 |
| ④ 确认/审批（>$5k） | CEO | 对超出自审范围的预算做最终决策 | 2小时内 |
| ⑤ 执行跟踪 | 运营部+财务部 | 运营部执行预算，财务部每周比对实际消耗与预算偏差 | 持续 |

**预算偏差阈值：**
- 🟢 偏差 < 10%：正常，运营部自主管理
- 🟡 偏差 10%~20%：运营部书面说明原因，报财务部备案
- 🔴 偏差 > 20%：暂停项目，上报CEO审批（同现有"预算超支"上报规则）

### 3.7.2 运营部 · DeepSeek API 费用管理

运营部使用 DeepSeek API 的项目，须配合财务部的预算追踪机制：

1. 每月初由财务部设定各项目的 API 费用预算上限
2. 运营部项目负责人每周检查 `data/budget/deepseek_balance.csv` 了解消耗情况
3. 触发 🔴 偏差 > 20% 时，运营部须在 24 小时内提交预算调整方案
4. 脚本 `scripts/budget-report.py` 可随时运行查看当前预算状态

## 四、例外上报机制

### 4.1 上报方式

```
普通例外 → 部门负责人书面说明（<200字）→ CEO 2小时内答复
紧急例外 → 即时通知CEO → CEO 30分钟内决策
重大事故 → CEO即时呈报董事长
```

### 4.2 上报内容规范

每条上报须包含：
1. **事由**：发生了什么
2. **影响范围**：影响哪些项目/部门
3. **建议方案**：上报人建议如何处理
4. **截止时间**：何时需要答复

### 4.3 越级上报

部门负责人不作为或判断严重失当，下属可直接向CEO报告。

## 五、授权撤销条件

CEO保留在以下情况下撤销授权、收回决策权：
1. 部门连续3次出现严重质量事故
2. 部门负责人明显越权决策
3. 部门运营指标（质量、效率）连续下降

## 六、运营模式

### 计划驱动

```
周一上午：各部门提交本周工作计划
周三：CEO抽查进展（无需每天汇报）
周五：各部门提交周报（3项成就 + 2项延迟 + 1项求助）
周六：CEO汇总呈报董事长
```

### 跨部门协作

部门之间可以直接协作，无需经CEO中转：
```
调研部 → 分析部：数据需求直接对接
调研部 → 创意部：排版需求直接对接
情报部 → 调研部：情报素材直接传递
运营部 → 财务部：预算申请直接对接
```
